# First-user trial

Status: not performed. Do not replace this with synthetic results or invented savings.

Ask one web development/design freelancer to use an explicitly non-confidential brief and a small delivery packet. Obtain their permission to use any feedback in the contest write-up separately from permission to try the app. No contact is automated.

1. Before using the app, ask how they normally check a delivery and explain it to a client. Record their answer, not an assumed problem.
2. Ask them to create a project, save a brief and review the model checklist. Note corrections, omissions, timeouts and questions.
3. Ask them to inspect a packet, select intended files and review matches. Include one deliberately imperfect synthetic item if their own packet is complete; label it synthetic.
4. Ask them to preview and download the handoff, then change one file and observe the stale review.
5. Ask: what was useful, what would stop use, what needs to fit their workflow, and whether they would use it on the next project.

Record completion/failure, assistance needed, errors and qualitative feedback. Record time only if measured consistently; a single trial cannot prove typical productivity improvements. Do not record precise locations, private contracts, client names, access credentials or raw private files in public evidence.

Release actions: fix task-blocking flaws, repeat failed steps, ask permission for any attributed quote and distinguish direct feedback from our interpretation. Keep a signed-off private evidence record out of Git. Publish only specifically approved, redacted facts.
