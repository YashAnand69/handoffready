# Facilitator and private feedback template

Status: trial not performed. Keep completed notes outside the repository (for example in the ignored local runtime directory). This blank template is safe to share; completed notes may not be.

## Run consistently

1. Ask permission to take notes. Explain no recording/publication is assumed. Record only a participant alias, relevant role and trial date.
2. Ask about their existing process before showing the demo. Do not explain the seeded faults or promise time savings.
3. Let them attempt each participant task without coaching. Note the first obstacle before offering help; mark every assisted step. Do not let them paste confidential material.
4. Label packet source (participant's non-confidential packet or synthetic sample), model mode (actual local AI/manual) and app checkpoint. Separate setup time from task time.
5. If timing, start/stop each task consistently and record interruptions. A single trial is not typical performance or proof of savings.
6. End with open questions before willingness-to-pay questions. Do not reward flattering answers.

## Convert findings into fixes

For each issue record reproduction steps, expected/observed behavior and severity. Prioritize loss of work, incorrect readiness and blocked core tasks, then confusion/repeated effort, then cosmetic preferences. Reproduce with synthetic data before changing code; add meaningful regression coverage. Repeat the failed task after the fix, clearly labelled as a second attempt.

## Publication permissions

Default: no public identity, quote, raw files or transcript. Ask separately for the exact proposed redacted excerpt and named destination (e.g. the DEV challenge entry). Record their approval privately. If permission is absent, don't publish it. Do not invent results, payments, acceptance or productivity metrics. Mark a synthetic demo as synthetic even if a real person tries it.
