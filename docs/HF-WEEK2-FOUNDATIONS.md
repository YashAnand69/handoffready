# Week 2: reusable foundations and original product decision

Research date: 13 October 2026 (Asia/Kolkata). This is a dependency and architecture assessment, not a completed installation, benchmark, legal opinion, or prediction of contest results. Hardware supplied by the parent audit: Apple M5 Pro, 24 GiB unified memory. All recommendations preserve the user's free-tier-only preference.

## Decision

Build an **original, narrowly scoped workflow on established open libraries and weights**. Do not train OCR or a language model from scratch. Do not fork a finished business application and replace its branding. Our defensible contribution should be the source-linked evidence model, review workflow, deterministic deliverable checks, user testing and distinctive interface. Identify reused components explicitly. Contest eligibility for new work and reuse must be checked against the rules report before development.

After the parallel competition/market examination, the preferred direction is **HandoffReady: accepted brief → delivery folder → evidence-backed handoff checklist**. Extract explicit requirements from a pasted or native-text PDF brief, ask the freelancer to approve the baseline, inspect a bounded delivery folder, and map each requirement to an actual supplied file and check result. Start with file presence, types, PNG dimensions and exact PDF text/page metadata; distinguish deterministic checks from human judgments. Show missing, contradictory and unverifiable items, then export an editable handoff packet. Do not claim automatic visual quality assessment, complete code auditing or contractual acceptance. A freelancer/small-agency tester is reachable, so this can produce better evidence than inventing a customer. This recommendation is provisional and does not demonstrate willingness to pay.

The initial generic scope/revision preference was superseded because the parent team's market research found multiple ScopeGuard applications and a DEV ScopeSlip entry; Framebase and Nexibeo also overlap generic revision management. Those findings belong to the accompanying market report. HandoffReady should concentrate on accepted-brief-to-deliverable evidence rather than repackage a generic scope-creep detector. The reusable foundation and model-validation findings below remain applicable.

### Docling details

Docling exports a structured document representation, Markdown and JSON, and supports local execution. Its official repository explicitly warns that model licenses must be checked independently of the MIT wrapper. The selected legacy model collection shows dual license labels; this is not permission to treat all present/future Docling pipelines as MIT. MPS is documented, but CPU fallback and measured per-page latency are necessary. Preserve page/paragraph provenance, inspect reading order, bound file size/pages and disable arbitrary URL fetches in intake. OCR errors can change deadlines or amounts. [Repository](https://github.com/docling-project/docling), [selected model card](https://huggingface.co/docling-project/docling-models), [accelerator example](https://docling-project.github.io/docling/_generated/examples/run_with_accelerator/), [current releases](https://github.com/docling-project/docling/releases/tag/v2.138.0).

### PaddleOCR details

PaddleOCR is an OCR/document toolkit, not a complete reliable order ledger. Its public release history is substantive, but the expanding Paddle/Transformers/backends increase integration choices. Start with a deliberately selected lightweight recognizer and its matching detector, not an arbitrary default that downloads unrecorded models. Verify local Apple Silicon wheels or an ONNX path before committing to screenshots as core input. Exact date, quantity and currency errors must be visibly editable. Never infer payment success from an OCR'ed screenshot. [Repository](https://github.com/PaddlePaddle/PaddleOCR), [release](https://github.com/PaddlePaddle/PaddleOCR/releases/tag/v3.7.0), [v6 recognition card](https://huggingface.co/PaddlePaddle/PP-OCRv6_medium_rec_safetensors), [v5 detector card](https://huggingface.co/PaddlePaddle/PP-OCRv5_mobile_det), [v5 recognizer card](https://huggingface.co/PaddlePaddle/PP-OCRv5_mobile_rec).

### Whisper details

The runtime officially reports base ~142 MiB disk / ~388 MB memory and small ~466 MiB / ~852 MB; these are upstream figures, not measurements on this Mac. Multilingual `small` is a sensible later test for consented voice notes; English-only variants should not be selected for Hindi/English mixed speech. Preserve the recording, timestamps and editable transcript. Ask for confirmation of names, dates and amounts before any quote. Add silence/music/noisy-input tests. Do not promise diarization or speaker identification. [Runtime and memory table](https://github.com/ggml-org/whisper.cpp), [maintenance release](https://github.com/ggml-org/whisper.cpp/releases/tag/v1.9.5), [original weights license](https://github.com/openai/whisper#license), [original model limitations](https://github.com/openai/whisper/blob/main/model-card.md).

### Embedding details

MiniLM produces 384-dimensional vectors, is English-focused, and truncates inputs beyond 256 word pieces by default. Split messages and clauses before encoding; preserve the original text and identifiers. It helps retrieve an already-agreed clause when the client paraphrases it. It does not prove entitlement, contradiction, acceptance or legal validity. Numeric differences require explicit comparison regardless of embedding score. Do not expose cosine similarity as a calibrated confidence percentage. [Framework](https://github.com/huggingface/sentence-transformers), [model card](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2), [release](https://github.com/huggingface/sentence-transformers/releases/tag/v6.1.0).

### Generative model details

Qwen3-4B is text-only and has thinking/non-thinking controls; choose bounded, non-thinking extraction for interactive latency and validate the output. The 0.6B model is useful to measure the quality/speed tradeoff, not a substitute for an evaluated 4B model. [4B card](https://huggingface.co/Qwen/Qwen3-4B), [0.6B card](https://huggingface.co/Qwen/Qwen3-0.6B), [official GGUF](https://huggingface.co/Qwen/Qwen3-4B-GGUF).

Gemma 4 E2B can accept text, image and audio, but multimodal capability alone does not remove transcription/OCR verification. Its official Q4 model page lists 3.35 GB; runtime caches and modality encoders require additional memory. On 24 GiB, a small quantized model is plausible; actual memory/latency and output quality remain unmeasured. Prefer text-only use first. [E2B model and parameter table](https://huggingface.co/google/gemma-4-E2B-it), [official Q4 model](https://huggingface.co/google/gemma-4-E2B-it-qat-q4_0-gguf), [Google Apache license](https://ai.google.dev/gemma/apache_2).

## Runtime and delivery choice

Prefer **llama.cpp's local server + a selected GGUF** for portable CPU/Metal inference and schema-constrained JSON. The runtime is MIT, supports Apple Silicon and quantization, and exposes an OpenAI-compatible API. Schema constraints control structure; they cannot establish that a claim is true. Disable unnecessary execution tools, bind to loopback and validate every returned source reference. [Runtime](https://github.com/ggml-org/llama.cpp), [server API and structured responses](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md), [schema implementation](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/server-schema.cpp).

MLX LM is an alternative MIT Apple Silicon Python runtime with quantization; use it if a verified selected checkpoint has a stable MLX conversion and better measured performance. It adds Mac-specific packaging and conversion provenance. Its default model is not our selected license/checkpoint. [MLX LM](https://github.com/ml-explore/mlx-lm), [release and Gemma 4 fixes](https://github.com/ml-explore/mlx-lm/releases/tag/v0.31.3).

Free hosting of a static frontend does **not** provide free persistent local-model inference. A public judge demo can include clearly marked, real recorded inference examples and an interactive review of those results; arbitrary live inference needs a real supported browser model or separately verified hosted compute. Do not repeat Soundwalk's ambiguity between a public workflow and desktop-only AI. Provide one explicit path, a setup guide and a concise actual-run video. No paid API, database or payment processor is needed to validate a pricing hypothesis this week.

## Proof required before committing to the stack

1. Build a small consented/redacted test pack plus synthetic adversarial examples: revised quantities, negation, ambiguous dates, contradictory requests, reused names, pasted instructions, missing evidence and multiple currencies. Separate examples used to improve prompts from held-out cases.
2. Test candidate models with the same schema, bounded context, original quotes and null/unknown fields. Record checkpoint revision/hash, runtime version, peak memory, cold/warm latency, valid-schema rate, field accuracy and unsupported-claim count. Decide from these measurements.
3. Reject model evidence unless its source ID exists and the quoted substring matches the supplied text. Model classification remains a suggestion; a person approves the requirement baseline and mappings. Requirements absent from the brief remain unknown. File presence does not establish visual quality or client acceptance.
4. Use integer minor units/Decimal for amounts and explicit unit/rate mappings. The model does not calculate totals or pick a market rate. Record user edits and do not call a suggestion legally binding.
5. Run a realistic baseline comparison with the reachable freelancer: manual task versus the app, correction burden, missed changes and whether they would pay/use it again. Report a hypothetical price as hypothetical; do not fabricate a customer or sale.
6. Preserve attribution/license notices and a dependency/model manifest. Put private client material outside the public repo and published fixtures. Verify accessibility, deletion, export, repeat visits and error recovery in the real browser.

## Research limitations

Public GitHub API release/commit metadata returned rate-limit errors. The maintenance evidence above comes from official release pages, not inferred popularity or an authenticated checkout. No models were downloaded, no Mac inference benchmark was run and no OCR backend was installed in this research task. Gemma 3 was inspected as a license contrast, then deliberately superseded by verified current Gemma 4 for the recommendation. Recheck exact dependency/model revisions when implementation starts.
