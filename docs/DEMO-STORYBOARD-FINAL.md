Preparation only, 15 October 2026. This is a proposed recording, not evidence that the steps have been performed or that a customer has used the app. Use a new synthetic project so earlier sample state does not silently turn the “before” into an already-corrected packet. ## The story

A freelancer is about to send a delivery that looks complete. The brief promises a transparent PNG and SVG logo, three distinct 1080 × 1080 PNG launch images, and instructions for changing the website contact email. The packet contains plausible-looking files, but presence alone is not fulfillment. HandoffReady brings the brief, file facts, model suggestions and a deliberate reviewer decision into one place.

The built-in Studio North sample uploads six files: `logo-opaque.png`, `logo.svg`, `launch-01.png`, `launch-02.png`, `launch-03-duplicate.png`, and `contact-guide.md`. The guide says only “Welcome to your new website.” The three launch filenames include two byte-identical originals. The opaque PNG has an alpha channel but no nonopaque pixels. These are authored synthetic fixtures, not discovered client mistakes.

## Before recording

- Run the current Codex project copy. Confirm the visible interface includes the latest motion pass; older videos do not.
- Use synthetic data only. Hide personal paths, tokens, unrelated tabs and real client material.
- Confirm whether Gemma is available. Use actual extraction/association for a Gemma demonstration. Manual operation is a valid fallback, but must be labelled manual and does not establish a model run.
- Check the actual approved requirements and selected evidence. Model proposals can vary; do not force a particular prediction for storytelling.
- Save a before record if needed to demonstrate immutability, then capture its hash and the after record separately. Distinguish scripted/sample decisions from customer approval.
- Prefer readable UI over exaggerated motion. Avoid rapid cuts, add captions, keep text on screen long enough to read, and omit decorative music if it masks the explanation.
- Capture a clean 1440-pixel-wide desktop view and optionally one brief mobile view. Browser viewport footage is not physical-device testing.
