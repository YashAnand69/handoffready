## The one task

A small web/design team needs to know what its outgoing packet actually supports, what a teammate's clarification changes and which reviewed record returned to the shared room. Show the agent carrying evidence and questions between the room and local reviewer; keep actual judgments visible as human actions.

Opening disclosure, on screen and in narration:

> “An assisted synthetic owner rehearsal. The owner used Discord and reviewed locally; an AI agent coordinated through Switch. Fixtures and some reply/reason wording were assistant-prepared. This is not an external colleague trial.”

The new event work extends the existing MIT HandoffReady review desk. Do not present the inherited UI/parsers/local-model evaluation as newly built for this event. The working room provider in the recorded loop was Antigravity through Switch's bounded CLI bridge; native custom MCP is not verified.

4. Show humans' deliberate packet, context, review and authorization actions. If an action is already completed and only history is available, label it “recorded history”; do not reauthorize, resend or toggle evidence simply to obtain a shot. 5. Keep tokens, private profile paths, login/account details, notifications, moderator key and unrelated rooms off screen. Use only authorized synthetic prose/files. A return record still shares approved titles/check descriptions/public notes, so inspect all visible words.
6. For every displayed finding, retain the actual type/status/reason and original file identity. Narrow byte/dimension/marker checks are not semantic design judgments. A manual requirement remains human-only even if metadata passes.
7. Show the actual downloaded returned Markdown for the final byte proof, not the local outgoing artifact. 8. If a return is uncertain or the provider is unavailable, show the honest retained state. Do not send again to force a green ending. A local desk restart is not proof of Switch/provider recovery. Follow the [recovery runbook](STAGE-5-RECOVERY.md).
9. Keep readable captions/transcript and enough dwell time to read the question, stale-state notice and operator-confirmed qualifier. Review the exported video at normal speed; verify cuts do not hide an unresolved hold or imply a human action was performed by the agent.

## Proposed voiceover for the core loop

“An assistant can move files and explanations, but the reviewer still needs a clear basis for a decision. Here the owner sends a synthetic packet in Discord. Switch's agent stages it, and the local lead confirms the complete revision.

“The agent raises a question tied to the saved requirement and files. The owner's reply is recorded as unverified context. The lead checks the source and deliberately uses it. That is context review, not delivery approval.

“The first assessment save was incomplete and needed guidance. After a current selected review, the owner supplies a correction. Confirming the new two-file packet makes the old assessment stale and retires the old context. The lead inspects the new evidence and records a fresh judgment.

“Finally, the lead previews the public record and fixed destination, then authorizes one return. The agent issues the exact frozen Markdown once. The owner downloads the real room attachment and checks its destination and bytes. That result is operator-confirmed, not independent transport authentication or client acceptance.

“This was an assisted synthetic owner rehearsal. A second-person trial and fresh independent evaluation are still pending. The host and configured chat/AI provider must be available; connected mode is not entirely local.”
