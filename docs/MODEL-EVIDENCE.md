## Local installation and privacy

Weights and compiled tools are ignored `.model/` and `.runtime/` artifacts. `scripts/prepare_model.py` validates SHA-256 before activation and every start. The server binds `127.0.0.1:18081`, context 8,192 tokens, one inference slot, alias `handoffready-gemma4-e2b`, an owner-only API-key file and CORS restricted to the app origin. No projector is loaded; only text inference is used. Original client bytes are not submitted to the model. The adapter accepts only bounded inspected text and metadata.

The adapter disables proxies and redirects and rejects configurable remote hosts. It counts the rendered chat prompt with the server's tokenizer, allows at most 6,000 input tokens and 1,500 output tokens, and times out a generation request at 60 seconds. Oversized text packets fail explicitly rather than being silently shortened. Structured generation is followed by strict schema validation, exact unique quote checks, and requirement/file ID checks. Text-bearing file associations require quoted evidence. Model suggestions never approve a baseline or mark a requirement satisfied.

## Measured feasibility and limitations

- Actual Mac hardware: Apple M5 Pro, ARM64, 25,769,803,776 bytes RAM (24 GiB).
- Source runtime compiled successfully, model weight SHA-256 verified, authenticated server running at the pinned path. Alias, real `/props` model path and chat template hash were verified.
- Recorded startup: **7.487 seconds** from launcher to healthy, including weight hash verification. Disk cache was uncontrolled; this is not a guaranteed cold-storage startup. Observed startup peak server RSS: **3,123,953,664 bytes**.
- Initial development V1: all four calls failed safely (two schema failures, two missing-quote failures). The first independently created synthetic evaluation also failed; neither report was replaced.
- Development V2–V4 exposed additional semantic errors: rewritten quotes, blocked-file proposals, mandatory PNG/SVG interpreted as an OR, omitted transparency, an excluded clause proposed as delivery, and an irrelevant invoice associated with a live website check. Raw diagnosis includes **synthetic inputs only**.
- V5 uses discriminated per-check grammar, mandatory quote fields, exact source-unit quote enums, known inspected-file IDs, explicit model obligation/association classifications and post-generation source validation. Model-classified optional/excluded clauses and unrelated associations are retained in local provenance with counts. This is still model interpretation, not proof of completeness or acceptance. Exact-text checks are human-added; model prose checks stay manual.
- V5 development: four actual calls completed. The predefined PNG/SVG/transparency/count/dimension probes passed, optional/excluded clauses were absent from published requirements, and all **4 matching rows** equaled predefined associations. Three semantic associations were missed by both frozen lexical baselines; the unsupported website test had no proposed files. This is one tuned synthetic packet, **not held-out accuracy**.
- V5 wall times: extraction **5.628 / 5.229 seconds** and matching **5.604 / 5.208 seconds**. Observed server RSS during these runs reached **2,134,966,272 bytes**. Memory sampling is per-process RSS; it does not measure every GPU/system allocation or establish deployment minimums.
- Independent fresh V2 evaluation: **4/4 calls completed; 5/6 matching rows** equaled predeclared associations. One missing CSV deliverable was wrongly associated with an inspected text file containing instruction-injection language. Its quote existed, so structural validation could not detect semantic irrelevance. This is a **failed semantic abstention control**, not a passed quality gate. No automatic satisfaction was granted; the user must reject the wrong suggestion. See `model-evaluation-heldout-v2.json` and the independently authored evaluation protocol.
- V6 matching definition was tightened after the fresh V2 failure: actual delivered content and file-type appropriateness, not mentions, self-description or requests to approve. The retired CSV case then retained both correct guide matches and left the missing CSV empty. This is a development regression recorded in `model-regression-v6-retired-v2.json`, not a new held-out success.
- V7 per-file grammar binds each file ID to its own unique exact text quote enum, or strictly null for nontext files. This repaired a metadata-only PNG quote failure found by the real API trial. `model-regression-v7-image.json` records a genuine accepted nonvisual PNG association.
- V7 original development rerun: all four calls completed, all predefined extraction probes passed, matching **4/4 rows** correct. Extraction first/warm **5.270 / 5.276 seconds**; matching first/warm **6.150 / 5.680 seconds**. Observed server RSS reached **2,181,709,824 bytes**. Fresh V3 then completed four actual calls with 4/5 exact matching rows: PNG/SVG and semantic guides were correctly associated, but a TXT future promise/instruction was wrongly associated with a missing PDF catalogue. Its original report is preserved as a failed abstention control.
- A deterministic approved-format guard was added after V3: validate quoted source and IDs first, then reject any suggested file whose inspected type is outside the union of approved presence/count formats plus PDF-pages/PNG-transparency types. It never invents substitute associations or guesses formats from natural language. Suppressed records retain original model reasoning, inspected type, allowed types and prior coverage. Empty results explicitly say no suggested files remain in required formats. Combined PNG/SVG requirements use a union, so a valid SVG is not rejected simply because a PNG is also required. This fixes a factual type mismatch, **not general prompt-injection security or semantic relevance**.
- `model-regression-v7-typed-guard-retired-v3.json` confirms the guard retained the valid guide and suppressed TXT-for-PDF in a real retired regression. V8 exposed merged source requirements, and V9 omitted transparency; those reports remain. V10 restores all original development attributes and 4/4 matching rows, with separate exact source sentences and PDF presence on the retired V3 regression. It still may omit a semantic content-review check on a document; human checklist review and disposition are required.
- Final V10 original development wall times: extraction **5.482 / 5.043 seconds**, matching **5.452 / 5.546 seconds**; observed server RSS maximum **1,987,018,752 bytes** in these runs. These tuned cases are regressions, not a new held-out evaluation or reliability statistic. Reports through V10 are retained with the original failure reports.
- Qwen alternative and first-user trial: not yet performed. V1/V2 fixtures cannot become held-out again after informing repairs. The tiny study cannot establish a real-world accuracy rate or selection superiority.

Reports remain separate: `model-benchmark-development.json`, `model-benchmark-development-v2.json`, `model-benchmark-development-v3.json`, `model-benchmark-development-v4.json`, `model-benchmark-development-v5.json`, `model-benchmark-development-v6.json`, and `model-benchmark-development-v7.json`, `model-benchmark-development-v9.json`, and `model-benchmark-development-v10.json`. `scripts/benchmark_model.py` uses a predeclared synthetic brief, three semantic documentation associations, one requirement requiring a manual live website check, unrelated billing text, and a blocked instruction-injection file. Both filename-only and filename-plus-text lexical comparators are frozen in code. Classification, source-validation failures and raw outputs must not be conflated with successful coverage.

Forty-three offline adapter boundary tests pass at this checkpoint. These synthetic-stub tests exercise schema, evidence, endpoint, token, HTTP deadline and classification handling; they are explicitly separate from real model quality. No private raw client prompts or outputs are persisted by the model adapter.
